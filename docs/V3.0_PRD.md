## 一、产品概述

### 1.1 产品愿景

**从"工具"到"时间社交平台"的第一步**

DaysFromToday V3.0 将实现从纯工具型产品向**时间可视化 + 轻量社交平台**的转型，让用户不仅能计算日期，还能：
- 将未来目标可视化为精美卡片
- 分享到社交媒体，获得点赞和留言
- 跨设备同步数据（登录后）
- 嵌入外部网站（倒计时组件）

### 1.2 产品定位

**Slogan**: "让未来可见，让期待可分享"

**核心价值**：
1. **可视化时间**：把抽象的"未来"变成具体的图文卡片
2. **轻量社交**：不登录也能分享、点赞、留言（降低门槛）
3. **情感连接**：让时间承载情感（期待、纪念、目标）

### 1.3 目标用户

| 用户类型 | 使用场景 | 核心需求 |
|---------|---------|---------|
| **个人用户** | 学习计划、健身目标、考试倒计时 | 时间规划、目标提醒 |
| **情侣/家庭** | 恋爱纪念日、宝宝生日 | 纪念日管理、情感记录 |
| **轻量团队** | 项目发布日、里程碑 | 团队倒计时、进度可视化 |

### 1.4 产品演进

```
V1.0：日期计算工具（纯功能）
  ↓
V2.0：日期计算 + 内容博客（工具 + SEO）
  ↓
V3.0：日期计算 + 轻量社交 + 可视化卡片（工具 + 内容 + 社交）  ← 当前版本
  ↓
V4.0：社区化平台（游戏化、排行榜、用户互动）（未来）
```

### 1.5 竞品差异化

| 产品 | 功能 | 我们的优势 |
|------|------|-----------|
| Countdown App（iOS） | 纯倒计时工具 | ✅ 可视化卡片 + 分享链接 |
| Days Matter（APP） | 纪念日 + 倒计时 | ✅ 无需下载 APP，网页即用 |
| Notion Timeline | 复杂项目管理 | ✅ 超轻量，200字即可生成卡片 |

### 2.2 功能 1：不必登录的轻量版「未来记事本」

#### 2.2.1 功能描述

用户在已有的日期计算页面（如 `/en/days/30`）直接输入目标，生成可视化卡片并分享。

#### 2.2.2 用户旅程

```
用户访问：/en/days/30（30天后是哪天）
  ↓
页面显示：2025-11-14（30天后的日期）
  ↓
新增输入框：「30天后，你想做什么？」
  ↓
用户输入目标（200字以内）
  - 实时字数统计：150/200
  - 超出后禁用"生成卡片"按钮
  ↓
点击"生成我的卡片"
  - 本地缓存（Zustand + LocalStorage）
  - 生成卡片预览
  ↓
用户可选：
  A. 下载图片（PNG/JPEG，适合社交媒体）
  B. 公开分享（生成短链接 + 点赞功能）
  C. 仅保存本地（私密模式）
```

#### 2.2.3 技术要点

- **本地缓存**：Zustand + LocalStorage（匿名用户最多 10 张）
- **图片生成**：`@vercel/og`（服务端渲染，1200x630）
- **短链接**：Cloudflare Workers KV（`https://dft.ai/c/abc123`）
- **字数限制**：200 字，实时计数器

#### 2.2.4 页面改动

```
现有页面：app/[locale]/days/[n]/page.tsx
新增组件：
  - components/GoalCardCreator.tsx
  - components/GoalInput.tsx
  - components/CardPreview.tsx
  - components/CardActions.tsx
```

### 2.4 功能 3：可嵌入的「倒计时组件」

#### 2.4.1 功能描述

提供一个轻量级的 `<iframe>` 嵌入代码，让外部用户可以在自己的网站/博客显示倒计时。

#### 2.4.2 使用场景

- **个人博客**：文章中嵌入"距离新书发布还有 X 天"
- **项目主页**：GitHub README 中显示"距离 V1.0 发布还有 X 天"
- **活动页面**：Notion/WordPress 嵌入倒计时

#### 2.4.3 用户旅程

```
用户访问：/embed/countdown
  ↓
填写表单：
  - 目标日期：2025-12-31
  - 显示文本："距离新年还有"
  - 样式选择：简约/卡片/进度条
  ↓
生成嵌入代码：
  <iframe src="https://dft.ai/w/abc123" width="300" height="100"></iframe>
  ↓
用户复制代码 → 粘贴到自己网站
```

#### 2.4.4 技术实现

**嵌入方式**：iframe（V3.0）+ Web Component（V3.1）

```html
<!-- iframe 方式 -->
<iframe 
  src="https://dft.ai/w/abc123" 
  width="300" 
  height="100"
  frameborder="0"
  scrolling="no"
></iframe>
```

**API 路由**：
```
app/api/widget/[id]/route.tsx
  - 读取组件数据（从 KV 或数据库）
  - 渲染 HTML（带样式）
  - 返回响应（可嵌入 iframe）
```

## 三、用户认证系统

### 3.1 认证策略：渐进式用户体验

```
匿名用户 → 轻度用户 → 登录用户 → 付费用户
   ↓           ↓           ↓           ↓
 快速体验    本地缓存    云端同步    高级功能
```

**设计原则**：
1. **先体验，后登录**：不强制登录，降低门槛
2. **数据驱动转化**：当用户积累 3+ 张卡片时，提示登录保存
3. **无缝迁移**：登录后自动同步本地数据到云端
4. **价值明确**：清晰告知登录的好处（跨设备、永久保存、高级功能）

### 3.2 支持的登录方式

| 登录方式 | 优先级 | V3.0 状态 | 说明 |
|---------|--------|----------|------|
| **Google OAuth** | ⭐⭐⭐⭐⭐ | ✅ 实现 | 主推方式，用户体验最佳 |
| **Magic Link** | ⭐⭐⭐⭐ | ✅ 实现 | 无需密码，安全便捷 |
| **Email + Password** | ⭐⭐⭐ | ✅ 实现 | 传统方式，折叠隐藏 |
| ~~GitHub OAuth~~ | ❌ | ❌ 移除 | 不再支持 |
| **Apple Sign In** | ⏳ | V3.1 | 未来扩展（移动端优先） |

### 3.3 认证技术选型

**选择：Supabase Auth**

**理由**：
- ✅ 与 Supabase 数据库无缝集成
- ✅ 自带 Row Level Security（RLS），数据安全
- ✅ 开箱即用的 Email/OAuth/Magic Link
- ✅ 免费额度充足（50K MAU）
- ✅ 开源，可自托管

### 3.4 登录提示策略

#### 场景 1：创建第 3 张卡片时

```
触发条件：用户创建 3 张卡片（本地缓存）
提示内容：
  💡 您已创建 3 张卡片
  登录后，您的卡片将永久保存并可跨设备访问
  [立即登录] [稍后再说]
```

#### 场景 2：本地数据同步

```
触发条件：用户登录成功 + 本地有未上传的卡片
提示内容：
  ☁️ 发现 3 张本地卡片
  是否同步到云端？同步后可跨设备访问
  [同步] [跳过]
```

### 3.5 登录的价值主张

| 功能 | 匿名用户 | 登录用户 |
|------|---------|---------|
| **卡片数量** | ≤ 10 张（本地） | 无限制 |
| **数据持久化** | 仅本地（易丢失） | ✅ 云端永久保存 |
| **跨设备同步** | ❌ | ✅ |
| **卡片模板** | 2 种基础模板 | 8+ 种模板 |
| **公开分享** | ✅ | ✅ |
| **点赞/留言** | ✅ 匿名点赞 | ✅ 实名点赞 + 留言 |
| **数据分析** | ❌ | ✅ 查看历史统计 |
| **提醒功能** | ❌ | ✅ Email 提醒（V3.1） |
| **导出数据** | ❌ | ✅ CSV/JSON 导出 |
| **品牌水印** | ✅ 有水印 | Pro 可去除（V3.1） |

### 3.6 会话管理

| Token 类型 | 有效期 | 刷新机制 |
|-----------|--------|---------|
| **Access Token** | 1 小时 | 自动刷新 |
| **Refresh Token** | 30 天 | 手动刷新或重新登录 |

**存储方式**：Cookie（HttpOnly, Secure, SameSite=Lax）

## 四、卡片模板系统

### 4.1 系统架构

```
模板层（Template Layer）
  ├── 布局引擎（Layout Engine）→ 控制元素位置
  ├── 样式引擎（Style Engine）→ 控制颜色/字体/效果
  └── 资源引擎（Asset Engine）→ 管理背景图片/图标

用户输入（User Input）
  ├── 内容数据（日期、文本、倒计时）
  ├── 样式选择（预设模板 or 自定义）
  └── 背景资源（预设渐变 or 上传图片）

渲染引擎（Render Engine）
  └── 输出：PNG/JPEG/SVG
```

### 4.2 模板类型

#### 方案一：渐变风格（Gradient Style）

**特点**：彩虹般的颜色过渡，玻璃拟态效果

**配色方案**（5 种）：

| 模板 ID | 名称 | 渐变色 | 适用场景 |
|---------|------|--------|---------|
| `gradient-professional` | 专业蓝紫 | #667EEA → #764BA2 | 工作目标、项目倒计时 |
| `gradient-romantic` | 浪漫粉红 | #F093FB → #F5576C | 恋爱纪念日、情人节 |
| `gradient-fresh` | 清新青蓝 | #4FACFE → #00F2FE | 健身目标、新年计划 |
| `gradient-growth` | 成长绿青 | #43E97B → #38F9D7 | 学习计划、考试倒计时 |
| `gradient-sunset` | 日落橙黄 | #FA709A → #FEE140 | 旅行计划、生日倒计时 |

**视觉元素**：
- 渐变背景（CSS Gradient）
- 玻璃拟态效果（半透明 + 毛玻璃）
- 白色文字 + 阴影
- 圆角卡片（16px）

#### 方案二：极简风格（Minimalist Style）

**特点**：干净简洁，黑白配色，单一强调色

**配色方案**（3 种）：

| 模板 ID | 名称 | 背景色 | 强调色 | 适用场景 |
|---------|------|--------|--------|---------|
| `minimalist-white` | 极简白色 | #FFFFFF | #0069FF（蓝） | 企业项目、打印需求 |
| `minimalist-dark` | 极简深色 | #1F2937 | #60A5FA（浅蓝） | 桌面壁纸、深色模式 |
| `minimalist-beige` | 极简米色 | #F5F5DC | #8B7355（棕） | 文艺风格、复古感 |

**视觉元素**：
- 纯色背景（Solid Color）
- 清晰的信息层次
- 最小化装饰元素
- 阴影效果（非玻璃拟态）

### 4.3 自定义背景上传

#### 4.3.1 功能流程

```
用户点击"上传图片"
  ↓
选择图片（JPG/PNG/WebP，≤ 5MB）
  ↓
前端预览 + 客户端压缩（可选）
  ↓
上传到 Cloudflare R2
  - 自动压缩：1920x1080，85% 质量，WebP 格式
  - 生成 CDN URL
  ↓
系统自动添加半透明遮罩层（rgba(0,0,0,0.3)）
  - 保证文字可读性
  ↓
实时预览 + 保存
```

#### 4.3.2 技术要点

- **图片压缩**：sharp 库（服务端）
- **存储**：Cloudflare R2（`backgrounds/{userId}/{imageId}.webp`）
- **遮罩层**：自动添加 30% 黑色遮罩（可调整）
- **限制**：
  - 格式：JPG/PNG/WebP
  - 大小：≤ 5MB
  - 尺寸：自动调整至 1920x1080

```
  ↓
保存到 Zustand（本地状态）
  ↓
保存到 LocalStorage（匿名用户）or Supabase（登录用户）
  ↓
调用 /api/og/goal-card 生成图片
  ↓
图片保存到 CDN（缓存）
  ↓
返回图片 URL + 短链接
  ↓
用户下载 or 分享
```

### 6.2 Row Level Security（RLS）策略

```sql
-- 用户只能查看自己的数据
CREATE POLICY "Users can view own data"
  ON users FOR SELECT
  USING (auth.uid() = id);

-- 用户可以查看公开的卡片或自己的卡片
CREATE POLICY "Users can view public or own cards"
  ON goal_cards FOR SELECT
  USING (is_public = TRUE OR user_id = auth.uid());

-- 用户只能创建属于自己的卡片
CREATE POLICY "Users can create own cards"
  ON goal_cards FOR INSERT
  WITH CHECK (user_id = auth.uid());

-- 用户只能更新自己的卡片
CREATE POLICY "Users can update own cards"
  ON goal_cards FOR UPDATE
  USING (user_id = auth.uid());

-- 用户只能删除自己的卡片
CREATE POLICY "Users can delete own cards"
  ON goal_cards FOR DELETE
  USING (user_id = auth.uid());

-- 允许匿名用户查看公开卡片
CREATE POLICY "Anonymous can view public cards"
  ON goal_cards FOR SELECT
  USING (is_public = TRUE);
```

2. 增加缓存层（相同卡片内容复用）
3. 限流策略（匿名用户 10 次/小时）
4. CDN 缓存生成的图片（Cache-Control: max-age=3600）

---

#### 风险 2：短链接滥用

**描述**：恶意用户批量生成短链接，消耗 KV 存储

**影响等级**：🟡 中

**规避方案**：
1. 限流：匿名用户 5 个/天，登录用户 50 个/天
2. 过期策略：90 天未访问自动删除
3. 人机验证：可疑行为触发 Turnstile（Cloudflare Captcha）
4. 监控告警：异常生成量触发通知

---

#### 风险 3：数据库迁移风险

**描述**：从 LocalStorage 迁移到 Supabase 时数据丢失

**影响等级**：🔴 高

**规避方案**：
1. 双写期：同时写入 LocalStorage 和 Supabase（2 周）
2. 数据校验：迁移后对比数据一致性
3. 回滚机制：保留 LocalStorage 数据 30 天
4. 用户提示：迁移前明确告知，获得同意

---

### 11.2 产品风险

#### 风险 4：用户隐私担忧

**描述**：用户担心目标内容被公开

**影响等级**：🟡 中

**规避方案**：
1. 默认私密：卡片默认不公开，需主动点击"分享"
2. 权限控制：支持"仅我可见"、"链接可见"、"公开"三档
3. 编辑/删除：用户随时可以修改或删除
4. 隐私声明：明确告知数据用途和保护措施

---

#### 风险 5：社交功能冷启动

**描述**：点赞/留言功能初期无人使用，显得冷清

**影响等级**：🟡 中

**规避方案**：
1. 运营策略：官方账号发布精选卡片，带动氛围
2. 激励机制：点赞数 ≥10 的卡片在首页展示
3. 社区规则：鼓励正向留言，禁止恶意评论
4. 分阶段：V3.0 仅上线点赞，V3.1 再加留言

---

### 11.3 商业风险

#### 风险 6：变现路径不清晰

**描述**：新功能是否能带来收入增长？

**影响等级**：🟡 中

**规避方案**：
1. MVP 验证：先上线基础功能，观察数据
2. 付费功能设计：
   - 免费：10 张卡片/月，基础模板
   - Pro：无限卡片，高级模板，无水印（$2.99/月）
3. B2B 探索：为企业提供品牌定制卡片（$49/月）
