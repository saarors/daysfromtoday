## 一、产品概述

### 1.1 产品定位

**Wish Books（愿望宝典）** 是 DaysFromToday 的核心内容模块，用时间维度记录人类目标与实现路径的百科全书。

**核心理念**：
> 从"几天后是哪天"到"这段时间能做什么"  
> 用时间刻度，让目标变得可见、可行、可参考

### 1.2 产品价值

| 对象 | 价值 |
|------|------|
| **用户** | 获得真实可行的目标案例 + 详细实施路径 + AI 个性化计划 |
| **产品** | 从工具型 → 内容型，建立内容护城河 |
| **SEO** | 100+ 高质量原创页面，覆盖长尾关键词 |
| **商业** | 内容资产积累 + 用户粘性提升 + 变现基础 |

### 1.3 与现有功能的关系

```
首页（日期计算）
    ↓ 引流
Wishlist（AI 目标规划）
    ↓ 内容沉淀
Wish Books（目标百科）← V3.4 新增
    ↓ 社交传播
用户投稿/UGC
```

**关键差异**：
- **Wishlist**：个人的、动态的、AI 生成的临时计划
- **Wish Books**：公共的、静态的、精选策展的永久内容

## 二、核心目标

### 2.1 业务目标

1. **内容资产积累**：6 个月内累积 100+ 高质量目标条目
2. **SEO 流量增长**：3 个月内目标页面贡献 30% 以上自然流量
3. **用户停留时间**：平均停留时间 > 3 分钟（vs 首页 < 1 分钟）
4. **社交传播**：每个条目平均分享次数 > 10 次

### 2.2 用户目标

1. **快速找到参考**：搜索"X天Y目标"直达相关条目
2. **获得可行路径**：看到真实案例 + 详细步骤
3. **启发灵感**：浏览不同时间维度的可能性
4. **创建个人计划**：从 Wish Books → 跳转到 Wishlist 生成 AI 计划

### 2.3 技术目标

1. **SEO 友好**：100% 静态生成（SSG + ISR）
2. **性能优异**：LCP < 2s，INP < 200ms
3. **内容可控**：简单后台，支持富文本 + 图片 + 视频
4. **维护成本低**：避免复杂的 Obsidian 工作流

## 三、功能需求

### 3.1 核心功能（MVP）

#### 功能 1：愿望卡片聚合页

**URL**：`/zh/wish-books`

**功能描述**：
- 展示所有已发布的愿望卡片
- 支持按时间维度筛选（7天、30天、90天、100天、180天、365天、3年、5年）
- 支持按类别筛选（健身、学习、职业、个人成长等）
- 支持搜索（标题 + 标签）
- 卡片网格布局（响应式：移动端 1 列，平板 2 列，桌面 3 列）

**优先级**：P0（必须）

---

#### 功能 2：愿望卡片详情页

**URL**：`/zh/wish-books/[slug]`（如：`/zh/wish-books/100-days-marathon`）

**功能描述**：
- 展示完整的目标实现方案
- 包含：标题、副标题、封面图、故事引入、路线图、真实案例、AI 建议、资源清单、FAQ、延伸阅读
- 支持富文本内容（Markdown 或 HTML）
- 支持图片和视频嵌入
- 底部 CTA：「创建我的计划」（跳转到 Wishlist）

**优先级**：P0（必须）

---

#### 功能 3：简单内容管理后台

**URL**：`/admin/wish-books`

**功能描述**：
- **卡片列表**：显示所有卡片（草稿、已发布、已归档）
- **创建卡片**：表单式编辑（标题、副标题、时间维度、类别、难度等）
- **富文本编辑器**：支持 Markdown 或 WYSIWYG（如 Tiptap）
- **图片上传**：拖拽上传到 Cloudflare R2，自动生成 URL
- **视频上传**：拖拽上传到 R2，自动生成播放器
- **预览功能**：保存草稿前可预览实际效果
- **一键发布**：发布后自动生成/更新静态页面

**优先级**：P0（必须）

---

#### 功能 4：SEO 优化

**功能描述**：
- 每个详情页自动生成：
  - 动态 `<title>` 和 `<meta description>`
  - Open Graph 和 Twitter Cards
  - JSON-LD 结构化数据（Article + FAQPage）
  - Canonical URL 和 hreflang
- 自动生成 sitemap（包含所有已发布卡片）
- 内链网络（相关卡片自动关联）

**优先级**：P0（必须）

---

## 五、内容管理方案

### 5.1 现有博客流程的问题

| 步骤 | 问题 |
|------|------|
| 1. Obsidian 编辑 | 需要安装 Obsidian，学习成本高 |
| 2. 图片处理 | 需要手动上传到 R2，路径容易出错 |
| 3. 内容同步 | 运行脚本 `npm run sync:obsidian`，容易忘记 |
| 4. Contentlayer 构建 | 需要重新 build，耗时长 |
| 5. 部署 | 需要 commit + push，流程长 |

**总结**：适合技术人员，不适合非技术内容创作者。

---

### 5.2 新方案：简单后台（推荐）

#### 核心思路

**数据库驱动 + 静态生成（SSG/ISR）**

```
内容存储：Supabase 数据库
    ↓
编辑工具：简单后台（Web UI）
    ↓
内容生成：Next.js SSG/ISR
    ↓
用户访问：静态 HTML（CDN）
```

#### 优势

| 特性 | 说明 |
|------|------|
| ✅ 简单易用 | Web 后台，无需安装软件 |
| ✅ 富文本编辑 | 支持 Markdown 或 WYSIWYG |
| ✅ 图片/视频 | 拖拽上传，自动处理 |
| ✅ 实时预览 | 保存前可预览效果 |
| ✅ SEO 友好 | 100% 静态生成 |
| ✅ 性能优异 | ISR 自动重新验证 |
| ✅ 成本可控 | 基于现有技术栈 |

### 5.4 内容发布流程

```
1. 登录后台
   /admin/wish-books
   
2. 点击"创建新卡片"
   填写基础信息：标题、时间维度、类别、难度等
   
3. 编辑内容
   - 使用富文本编辑器撰写正文
   - 拖拽上传封面图、配图、视频
   - 填写路线图、案例、资源等结构化内容
   
4. 预览
   查看实际渲染效果
   
5. 保存草稿
   内容保存到数据库，status = 'draft'
   
6. 发布
   - 点击"发布"按钮
   - status 改为 'published'
   - 触发 ISR 重新验证，生成静态页面
   
7. 用户访问
   /zh/wish-books/[slug]
   直接返回静态 HTML
```

**时间成本**：
- 创建一个卡片：30-60 分钟
- 发布到线上：< 2 分钟（自动）

---

### 5.5 内容增删改流程

#### 增加（Create）

```
后台 → 创建新卡片 → 填写内容 → 保存草稿 → 预览 → 发布
    ↓
数据库新增一条记录（status = 'published'）
    ↓
触发 ISR，生成静态页面
    ↓
Sitemap 自动更新
```

#### 修改（Update）

```
后台 → 编辑卡片 → 修改内容 → 保存
    ↓
数据库更新记录（updated_at 更新）
    ↓
触发 ISR，重新生成静态页面
    ↓
用户在 1 小时内看到最新内容（revalidate = 3600）
```

**可选：立即更新**
- 提供"立即刷新"按钮
- 调用 `/api/revalidate` 强制重新生成

#### 删除（Delete）

```
后台 → 删除卡片（软删除）
    ↓
数据库记录 status 改为 'archived'
    ↓
静态页面返回 404
    ↓
Sitemap 自动移除该页面
```

**硬删除**（可选）：
- 真正从数据库删除记录
- 同时删除关联的图片/视频

## 九、风险与约束

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| ISR 失效 | 内容更新不及时 | 提供手动刷新按钮 |
| 图片加载慢 | 用户体验差 | 使用 CDN + 懒加载 + WebP |
| 视频占用空间 | 成本增加 | 限制视频大小（< 50MB）|
| 富文本编辑器 Bug | 内容格式错乱 | 充分测试 + 预览功能 |

---

### 9.2 内容风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 内容质量参差不齐 | SEO 受损 | 人工审核 + 质量评分系统 |
| 内容雷同（重复） | 搜索引擎降权 | 查重工具 + 差异化策略 |
| 版权问题（图片/案例）| 法律风险 | 使用自有素材 + 授权图片 |

### 9.3 成本约束
