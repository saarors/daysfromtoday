## 🎯 实施目标

构建一个**完全本地化、可人工编辑、高性能**的节假日数据管理系统，替代对外部 API 的完全依赖。

### 核心需求（已全部满足）

1. ✅ **配置文件格式**: Markdown（人工友好）
2. ✅ **基础数据来源**: Nager.Date API（自动抓取）
3. ✅ **语言支持**: 仅维护英文+中文，其他语言自动翻译
4. ✅ **时间跨度**: 2025、2026、2027、2028（4年）
5. ✅ **不改变前端**: 仅优化后台数据层

## 🏗️ 技术架构

### 数据流

```mermaid
graph LR
    A[用户请求] --> B{getHolidays}
    B --> C[本地 Markdown]
    C -->|成功| E[返回数据]
    C -->|失败| D[Nager.Date API]
    D -->|成功| E
    D -->|失败| F[空数据]
    F --> E
```

### 数据优先级

1. **本地 Markdown 配置**（主源）
   - 响应速度: <5ms
   - 准确性: 95%+（人工验证后）
   - 可控性: 100%

2. **Nager.Date API**（降级）
   - 响应速度: 200-1000ms
   - 准确性: 85-90%
   - 可控性: 0%

3. **空数据**（兜底）
   - 确保应用不崩溃

### Markdown 格式设计

```markdown
# 🇨🇳 中国 (China)

> **数据来源**: 国务院办公厅 + Nager.Date API  
> **最后更新**: 2025-10-08  
> **维护状态**: ⏳ 待验证  

---

## 2025年

### 元旦 | New Year's Day
- **日期**: 2025-01-01
- **类型**: 公共假期 (Public Holiday)
- **全国性**: 是
- **说明**: 法定节假日
```

**优势**:
- ✅ 易于人工编辑
- ✅ Git Diff 清晰
- ✅ 支持富文本说明
- ✅ 版本管理友好

## 🔧 NPM 脚本命令

### 已添加的命令

```json
{
  "scripts": {
    "holidays:init": "tsx scripts/generate-holidays.ts init",
    "holidays:update": "tsx scripts/generate-holidays.ts update",
    "holidays:validate": "tsx scripts/validate-holidays.ts"
  }
}
```

### 使用示例

```bash
# 初始化所有国家数据
npm run holidays:init

# 更新单个国家
npm run holidays:update CN

# 验证数据格式
npm run holidays:validate
```
