## 🔥 问题总结

### 主要问题

**V3.1 API 完全挂起，导致页面无响应**

- **现象**: `stream` 请求一直处于 `Pending` 状态
- **影响**: 用户无法使用 AI 功能，页面卡死
- **严重程度**: P0（阻塞性问题）

## 🔍 根本原因分析

### 1. **使用了错误的 Supabase Client** ❌

**问题代码**:

```typescript
// ❌ lib/v3.1/prompt-composer.ts (Line 14)
import { createClient } from '@/lib/supabase/client';

// ❌ lib/v3.1/methodology-matcher.ts (Line 14)
import { createClient } from '@/lib/supabase/client';
```

**问题原因**:
- `@/lib/supabase/client` 是**客户端 Client**，只能在浏览器中使用
- **Edge Runtime API 必须使用服务器端 Client**
- 客户端 Client 在服务器端会导致：
  - 无法正确初始化
  - Cookie 和 Session 无法访问
  - 数据库查询挂起或失败

**正确做法**:

```typescript
// ✅ 服务器端 API 必须使用这个
import { createClient } from '@/lib/supabase/server';
```

---

### 2. **Edge Runtime 中使用 console.log 导致问题** ⚠️

**问题代码**:

```typescript
// ❌ 在 Edge Runtime 流式响应中使用 console.log
console.log('[PromptComposer] 开始组装 Prompt', { criteria, variables });
console.log('[MethodologyMatcher] 匹配成功', { code, name, score });
```

**问题原因**:
- Edge Runtime 对 `console.log` 有限制
- 特别是在流式响应处理中
- 复杂对象序列化可能导致性能问题或阻塞

**解决方案**:
- 移除所有 `console.log`、`console.warn`
- 仅保留必要的 `console.error`（错误场景）
- 使用 Response Headers 传递调试信息

---

### 3. **缺少超时保护** ⚠️

**问题**:
- 数据库查询没有超时机制
- 如果查询慢或挂起，整个 API 会永久等待
- 导致用户体验极差

**原有代码**:

```typescript
// ❌ 没有超时保护
const template = await this.queryPromptTemplate(criteria);
```

**修复后**:

```typescript
// ✅ 添加 3 秒超时
const template = await Promise.race([
  this.queryPromptTemplate(criteria),
  new Promise<null>((resolve) => setTimeout(() => resolve(null), 3000))
]);
```

### 3. 添加超时保护

**文件**: `lib/v3.1/prompt-composer.ts`

```typescript
static async compose(
  criteria: PromptQueryCriteria,
  variables: PromptVariables
): Promise<ComposedPrompt> {
  try {
    // ✅ 第1步: 带 3 秒超时
    const template = await Promise.race([
      this.queryPromptTemplate(criteria),
      new Promise<null>((resolve) => setTimeout(() => resolve(null), 3000))
    ]);

    if (template) {
      return await this.composeFromDatabase(template, variables, criteria);
    }

    // ✅ 第2步: 带 2 秒超时
    const fallbackTemplate = await Promise.race([
      this.queryFallbackTemplate(criteria),
      new Promise<null>((resolve) => setTimeout(() => resolve(null), 2000))
    ]);

    if (fallbackTemplate) {
      return await this.composeFromDatabase(fallbackTemplate, variables, criteria);
    }

    // ✅ 第3步: 硬编码降级（无超时）
    return this.composeFromHardcoded(variables, criteria);

  } catch (error) {
    // ✅ 任何错误都降级到硬编码
    return this.composeFromHardcoded(variables, criteria);
  }
}
```

**超时策略**:
1. 第1步（精确匹配）: 3秒
2. 第2步（通用模板）: 2秒
3. 第3步（硬编码）: 无超时（立即返回）

**总超时时间**: 最多 5 秒（加上 DeepSeek API 调用时间）

## 📝 经验教训

### 1. **Edge Runtime 的特殊性** 🚨

- ❌ **不能**使用客户端 Supabase Client
- ❌ **不能**随意使用 console.log（特别是流式响应中）
- ❌ **不能**依赖 Node.js 特定的 API
- ✅ **必须**使用服务器端 Client
- ✅ **必须**谨慎使用日志
- ✅ **必须**添加超时保护

### 2. **数据库查询的超时保护** ⏱️

**所有异步数据库查询都应该有超时机制：**

```typescript
// ✅ 正确做法
const data = await Promise.race([
  fetchData(),
  timeout(3000)
]);

// ❌ 错误做法
const data = await fetchData(); // 可能永久挂起
```

### 3. **调试 Edge Runtime 的正确方式** 🔍

**不推荐**: `console.log`

**推荐**:
1. **Response Headers**:
   ```typescript
   return new Response(stream, {
     headers: {
       'X-Debug-Source': 'database',
       'X-Debug-Fallback': '0'
     }
   });
   ```

2. **前端 Console + Network 面板**:
   - 查看请求状态
   - 查看 Response Headers
   - 查看 Response 内容

3. **环境变量控制日志级别**:
   ```typescript
   if (process.env.DEBUG === 'true') {
     // 仅在开发环境打印
   }
   ```

### 4. **渐进式升级策略** 📈

**重大功能升级应该分阶段进行：**

1. **阶段1**: 实现基础功能（无数据库，硬编码）
2. **阶段2**: 添加数据库查询（带完整错误处理）
3. **阶段3**: 添加高级功能（方法论匹配等）
4. **阶段4**: 优化性能和用户体验

**每个阶段都要：**
- ✅ 充分测试
- ✅ 确保降级策略生效
- ✅ 验证不会阻塞主流程

### 5. **降级策略的重要性** 🛡️

**V3.1 的三层降级策略：**

```
数据库精确匹配 (3s timeout)
    ↓ (失败)
数据库通用模板 (2s timeout)
    ↓ (失败)
硬编码模板 (无超时，100% 可用)
```

**关键原则**:
- 永远不要让新功能阻塞核心流程
- 降级后的体验应该接近原始体验
- 最后一层降级必须 100% 可靠
