## 🔧 实现方案

### 1. 数据存储

#### 数据库字段更新
在保存卡片时，将任务列表保存到 `matching_metadata` JSONB 字段中：

```typescript
matching_metadata: {
  ...cardData.matchingMetadata,
  // V3.1.1: 添加动态任务列表
  task_list: dynamicTasks.length > 0 ? dynamicTasks : null,
}
```

**字段结构**:
```json
{
  "detected_keywords": ["健身", "运动"],
  "confidence_score": 0.85,
  "difficulty_score": 0.6,
  "persona_reasoning": "...",
  "matched_at": "2025-11-06T...",
  "task_list": [
    "评估当前体能基线，制定合理起点",
    "每周进行3次30分钟有氧运动",
    "逐步增加运动强度和时长",
    "每周记录进度并调整计划"
  ]
}
```

### 2. ViewOnly 模式加载

#### 恢复任务列表
在 `viewOnly` 模式下，从卡片数据中恢复任务列表：

```typescript
// V3.1.1: 恢复动态任务列表
if (card.matchingMetadata?.task_list && Array.isArray(card.matchingMetadata.task_list)) {
  console.log('📋 viewOnly模式: 恢复任务列表', card.matchingMetadata.task_list);
  setDynamicTasks(card.matchingMetadata.task_list);
}
```

### 3. UI 渲染逻辑

#### 任务列表显示
修改条件渲染逻辑，同时支持 `viewOnly` 和非 `viewOnly` 模式：

```typescript
{/* 任务列表 - viewOnly 和非 viewOnly 模式都显示 */}
{((goalData?.viewOnly && dynamicTasks.length > 0) || 
  (!goalData?.viewOnly && (streaming.isStreaming || streaming.thinking || ...))) && (
  <ThinkingTaskList 
    hasContent={!!(streaming.thinking || streaming.content || goalData?.viewOnly)}
    dynamicTasks={dynamicTasks}
    isLoading={tasksLoading}
  />
)}
```

**关键点**:
- `viewOnly` 模式：当 `dynamicTasks.length > 0` 时显示
- `hasContent` 设置为 `true`，任务列表立即显示为"已完成"状态
- 无加载动画，直接静态展示

#### AI 建议思路显示
从 `viewOnlyContent` 中提取 `<think>` 标签内容：

```typescript
{/* AI 思考过程 - viewOnly 和非 viewOnly 模式都显示 */}
{((goalData?.viewOnly && viewOnlyContent) || 
  (!goalData?.viewOnly && (streaming.thinking || streaming.snapshotThinking()))) && (
  <div className="bg-purple-50/30 rounded-xl p-4 mb-3 border border-purple-200/50">
    <div className="flex items-center gap-2 mb-1.5">
      {/* 灯泡图标 */}
      <svg className="w-4 h-4 text-purple-600" fill="none" viewBox="0 0 24 24" stroke="currentColor">
        <path strokeLinecap="round" strokeLinejoin="round" strokeWidth={2} d="M9.663 17h4.673M12 3v1m6.364 1.636l-.707.707M21 12h-1M4 12H3m3.343-5.657l-.707-.707m2.828 9.9a5 5 0 117.072 0l-.548.547A3.374 3.374 0 0014 18.469V19a2 2 0 11-4 0v-.531c0-.895-.356-1.754-.988-2.386l-.548-.547z" />
      </svg>
      <span className="text-sm font-medium text-purple-900">
        AI 的建议思路
      </span>
    </div>
    <div className="whitespace-pre-wrap text-sm text-gray-700 leading-relaxed">
      {goalData?.viewOnly 
        ? viewOnlyContent.match(/<think>([\s\S]*?)<\/think>/)?.[1]?.trim() || '暂无推理过程'
        : (streaming.thinking || streaming.snapshotThinking())
      }
    </div>
  </div>
)}
```

**正则提取逻辑**:
- 匹配 `<think>...</think>` 标签
- 提取标签内部内容
- 去除首尾空白
- 如果没有匹配到，显示"暂无推理过程"

## 🐛 潜在问题与解决方案

### 问题 1: 老卡片没有任务列表
**现象**: V3.1.1 之前的卡片，`matching_metadata.task_list` 为 `null` 或不存在

**解决方案**: 
- 已在代码中添加检查：`if (card.matchingMetadata?.task_list && Array.isArray(card.matchingMetadata.task_list))`
- 如果没有任务列表，任务列表区域不显示

**优化方向**（可选）:
- 可以为老卡片生成任务列表（调用 `/api/ai/task-decomposition`）
- 或者显示默认任务列表

### 问题 2: `<think>` 标签不存在
**现象**: AI 响应中没有 `<think>` 标签

**解决方案**:
- 正则匹配失败时返回 `undefined`
- 使用 `|| '暂无推理过程'` 作为降级方案

### 问题 3: 详情页刷新后内容消失
**状态**: ✅ 已在 V3.1 修复
**原因**: `useEffect` 依赖项不正确
**解决方案**: 依赖 `wishCards` 和 `searchParams`，确保数据加载完成后再恢复状态

## 📊 性能考虑

### 数据库影响
- `matching_metadata` 是 JSONB 字段，添加 `task_list` 不影响现有结构
- 任务列表通常 2-5 条，每条 40 字以内，数据量很小（< 500 bytes）

- 正则提取 `<think>` 标签性能影响可忽略（O(n) 复杂度，n 为内容长度）
