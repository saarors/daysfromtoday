## 🔴 Incident #001 - 页面 404 错误 (V3.1 API 切换后)

**发生时间**: 2025-11-05 00:20  
**问题等级**: P1 (高优先级)  
**影响范围**: 整个应用无法访问

### 1. 问题描述

用户访问 `http://localhost:3009/` 时出现 404 错误：
```
404
This page could not be found.
```

**上下文**:
- 刚刚完成 V3.1 API 切换
- 旧版 API 备份为 `route.v3.0.backup.ts`
- 新版 API 启用为 `route.ts`
- 开发服务器在后台运行

### 2. 诊断过程

使用诊断脚本 `npm run diagnose`，结果：

```bash
━━━ 1️⃣ 端口检查 ━━━
❌ 端口 3009 被占用 (PID: 29162, 88654)

━━━ 2️⃣ 文件句柄限制 ━━━
✅ 文件句柄限制充足: 1048575

━━━ 3️⃣ 编译缓存 ━━━
⚠️  编译缓存存在: 74M

━━━ 4️⃣ 依赖包 ━━━
✅ node_modules 存在

━━━ 5️⃣ 环境变量 ━━━
✅ .env.local 存在
✅ SUPABASE_URL 已配置
✅ SUPABASE_ANON_KEY 已配置
```

**关键发现**:
1. 端口被 2 个旧进程占用
2. 编译缓存过期（74MB）

### 3. 根本原因

**问题类型**: A类高频问题 - Next.js 编译缓存过期 + 端口占用

**详细分析**:
- **直接原因**: 修改了 API 文件（route.ts），但 Next.js 编译缓存未更新
- **间接原因**: 后台启动的服务器没有正确初始化，导致旧进程残留
- **触发条件**: 
  1. 重命名 API 文件（`route.v3.1.ts` → `route.ts`）
  2. 后台启动服务器（`is_background: true`）
  3. 编译缓存中的路由注册表未刷新

### 4. 解决步骤

按照 `SYSTEM_TROUBLESHOOTING.md` 中的标准流程：

```bash
# Step 1: 停止所有占用端口的进程
lsof -ti:3009 | xargs kill -9

# Step 2: 清理编译缓存
rm -rf .next

# Step 3: 重启开发服务器
ulimit -n 10240 && PORT=3009 npm run dev
```

**注意事项**:
- 停止进程需要 `all` 权限（沙箱限制）
- 必须清理 `.next` 缓存，否则路由不会更新


3. **避免后台启动服务器**
   - 问题: `is_background: true` 可能导致进程残留
   - 解决: 使用前台启动，或者确保后台进程正确管理

#### 长期措施（后续优化）

## 🟢 Incident #002 - ERR_CONNECTION_REFUSED (服务器进程终止)

**发生时间**: 2025-11-05 00:25  
**问题等级**: P2 (中优先级)  
**影响范围**: 整个应用无法访问

### 1. 问题描述

用户访问 `http://localhost:3009/` 时出现连接拒绝错误：
```
ERR_CONNECTION_REFUSED
localhost 拒绝了我们的连接请求。
```

**上下文**:
- 刚刚完成 Incident #001 的修复
- 使用后台模式启动服务器
- 服务器进程意外终止

### 2. 诊断过程

```bash
# 检查端口
lsof -ti:3009
# 结果: 无进程（端口空闲）

# 查看日志
tail -100 /tmp/daysfromtoday-dev.log
# 结果: 显示之前正常运行的日志，但进程已终止
```

**关键发现**:
- 端口完全空闲（没有进程）
- 日志显示之前服务器正常运行过
- 进程在后台意外终止

### 3. 根本原因

**问题类型**: 服务器进程意外终止

**详细分析**:
- **直接原因**: 后台启动的 Node.js 进程终止
- **可能原因**: 
  1. 后台进程没有正确守护（daemon）
  2. 进程遇到未捕获的错误
  3. 系统资源限制导致进程被杀死
  4. 终端会话结束时后台进程被清理

### 4. 解决步骤

使用新创建的标准重启脚本：

```bash
npm run restart
```

此命令自动完成：
1. 停止旧进程（如果有）
2. 清理编译缓存
3. 设置文件句柄限制
4. 启动服务器

### 5. 耗时统计

| 阶段 | 耗时 |
|-----|------|
| 问题报告 | 即时 |
| 诊断分析 | 30 秒 |
| 重启服务器 | 15 秒 |
| 验证修复 | 5 秒 |
| **总计** | **约 1 分钟** |

### 6. 预防措施

#### 短期措施（立即执行）

1. **使用标准重启命令**
   ```bash
   npm run restart
   ```

2. **不要依赖后台启动**
   - 后台启动不稳定
   - 错误信息不可见
   - 进程管理困难

#### 长期措施（后续优化）

1. **使用进程管理工具**
   
   考虑使用 PM2 或 nodemon 来管理开发服务器：
   ```bash
   # 安装 PM2
   npm install -g pm2
   
   # 使用 PM2 启动
   pm2 start "PORT=3009 npm run dev" --name daysfromtoday
   
   # 查看状态
   pm2 status
   
   # 查看日志
   pm2 logs daysfromtoday
   ```

2. **添加健康检查**
   
   创建 `scripts/health-check.sh`:
   ```bash
   #!/bin/bash
   
   # 检查服务器是否响应
   curl -f http://localhost:3009 > /dev/null 2>&1
   
   if [ $? -eq 0 ]; then
     echo "✅ 服务器正常运行"
     exit 0
   else
     echo "❌ 服务器无响应，自动重启..."
     npm run restart
   fi
   ```

3. **监控服务器进程**
   
   可以使用 `watch` 命令持续监控：
   ```bash
   watch -n 5 'lsof -ti:3009 && echo "✅ 运行中" || echo "❌ 已停止"'
   ```
