## 一、内容原则

### 1.1 核心定位

**DaysFromToday 博客的定位**:
- 🎯 **主题**: 时间管理、日期计算、生产力提升
- 💡 **风格**: 有温度、可读性强、实用性高
- 👥 **受众**: 普通用户（非技术背景）
- 📚 **层次**: 温度层（情感共鸣）+ 应用层（实用技巧）

### 1.2 内容分层

**温度层内容**（30%）:
- 个人故事和经历
- 情感共鸣和价值观
- 时间的哲学思考
- 用户案例和故事

**示例**:
- "为什么我要做 DaysFromToday"
- "时间的 10,000 小时法则是真的吗？"
- "我如何用倒计时改变拖延症"

**应用层内容**（70%）:
- 实用技巧和教程
- 工具使用指南
- 数据和案例分析
- 问题解决方案

**示例**:
- "5 个提升工作效率的时间管理工具"
- "如何计算项目截止日期？"
- "纪念日提醒完全指南"

### 1.3 质量原则

1. **质量优先**: 一篇精品文章 > 十篇粗糙文章
2. **用户为先**: 解决实际问题，提供实际价值
3. **可读性强**: 小学六年级学生能看懂
4. **图文并茂**: 图片传递信息，而非装饰
5. **SEO 友好**: 自然融入关键词，结构清晰

## 二、图片规范

### 2.1 图片类型与规格

> **智能处理原则**: 所有尺寸和体积限制都是**推荐值**，而非硬性限制。脚本会自动优化，确保图片质量和性能平衡。

#### Hero 图（文章封面）

**用途**: 文章顶部，吸引注意力，传递主题

**推荐规格**:
- 尺寸: 1200×630px（符合 OG 标准）
- 格式: WebP + JPEG 降级
- 质量: 85
- 体积: <150KB（WebP），<250KB（JPEG）

**自动处理规则**:
- ✅ **过大图片**（>3MB）: 自动压缩到 85 质量，若仍超标则逐步降低质量直到 <250KB
- ✅ **尺寸不符**: 智能裁剪到 1200×630（优先保留中心内容）
- ✅ **比例不符**: 
  - 横图（宽>高）: 裁剪到 1200×630
  - 竖图（高>宽）: 添加模糊背景填充到 1200×630（类似 Instagram）
  - 正方形: 智能填充到 1200×630
- ✅ **格式转换**: 自动生成 WebP（现代浏览器）+ JPEG（兼容性）

**设计要点**:
- 简洁大气，突出主题
- 可包含标题文字（字号大、对比度高）
- 色彩饱和但不刺眼
- 避免过于复杂的元素

#### 正文插图

**用途**: 段落间穿插，辅助理解，增强可读性

**推荐规格**:
- 尺寸: 800px 宽（正文宽度）
- 格式: WebP + JPEG 降级
- 质量: 85
- 体积: <100KB（WebP），<150KB（JPEG）

**自动处理规则**:
- ✅ **宽度 >800px**: 等比缩放到 800px
- ✅ **宽度 <800px**: 保持原尺寸（不放大，避免失真）
- ✅ **长图**（高>宽×2）: 保持原比例，不裁剪
- ✅ **超大文件**: 自动压缩，优先保证清晰度

**类型**:
- 产品截图（功能展示）
- 概念示意图（流程、关系）
- 对比图（前后对比）
- 装饰插图（氛围营造）

#### 图表 / 数据可视化

**用途**: 呈现数据、趋势、对比

**推荐规格**:
- 尺寸: 800-1200px 宽
- 格式: PNG（保留清晰度）+ WebP 降级
- 质量: 90
- 体积: <200KB

**自动处理规则**:
- ✅ **图表特殊处理**: PNG 格式优先（保留锐利边缘）
- ✅ **宽度自适应**: 800-1200px 范围内保持原尺寸
- ✅ **超宽图**: 缩放到 1200px
- ✅ **质量优先**: 图表类图片质量设为 90（高于普通图片）

**设计要点**:
- 标题清晰（标明数据主题）
- 坐标轴明确（单位、刻度）
- 颜色区分清晰（最多 5 种颜色）
- 数据来源标注（"来源: Google Analytics"）

#### 缩略图 / 列表图

**用途**: 博客列表页、相关文章推荐

**推荐规格**:
- 尺寸: 400×225px（16:9 比例）
- 格式: WebP + JPEG 降级
- 质量: 80
- 体积: <50KB（WebP），<80KB（JPEG）

**自动处理规则**:
- ✅ **自动生成**: 从 Hero 图自动裁剪生成
- ✅ **智能裁剪**: 优先保留中心内容
- ✅ **激进压缩**: 质量 80，确保体积 <50KB

### 2.2 智能图片处理（自动化）

> **核心理念**: 用户只需上传原图，脚本自动处理一切优化工作

#### 场景 1: 处理过大图片（>3MB）

**问题**: 上传了 5MB 的高清图片

**自动处理流程**:
```
1. 检测文件大小: 5MB > 3MB 阈值
2. 智能压缩:
   - 第一轮: 质量 85 → 生成 WebP + JPEG
   - 检查体积: 若仍 >250KB
   - 第二轮: 质量 80 → 重新生成
   - 检查体积: 若仍 >250KB
   - 第三轮: 质量 75 → 重新生成
   - 持续降低直到达标
3. 输出:
   - hero.webp (120KB, 质量 80)
   - hero.jpg (200KB, 质量 80)
   - ✅ 压缩率: 96%（5MB → 200KB）
```

**用户无需操心**: 脚本自动找到最佳质量/体积平衡点

#### 场景 2: 处理比例不符的图片

**问题 A: 上传了竖图（1080×1920，手机截图）**

**自动处理**:
```
检测比例: 高 > 宽（竖图）
目标: 1200×630（OG 标准）

处理方案（Instagram 风格）:
1. 原图高斯模糊 → 作为背景（1200×630）
2. 原图缩放适配 → 居中叠加
3. 输出:
   ┌─────────────────┐
   │  [模糊背景]      │
   │  ┌─────────┐   │
   │  │  原图   │   │ 1200×630
   │  │ 居中   │   │
   │  └─────────┘   │
   └─────────────────┘

✅ 无变形，保留完整内容
```

**问题 B: 上传了正方形图片（1000×1000）**

**自动处理**:
```
检测比例: 宽 = 高（正方形）
目标: 1200×630

处理方案:
1. 智能裁剪: 保留中心 1000×525 区域
2. 或添加背景: 模糊填充到 1200×630
3. 用户可选: --crop（裁剪）或 --fill（填充）

✅ 默认填充模式，避免丢失内容
```

**问题 C: 上传了超宽图（2400×800，横幅）**

**自动处理**:
```
检测比例: 宽 > 高×2（超宽）
目标: 1200×630

处理方案:
1. 智能裁剪:
   - 检测主体（人脸、文字、明显物体）
   - 优先保留主体区域
   - 裁剪到 1200×630
2. 输出报告:
   "已裁剪到 1200×630，主体居中"

✅ 智能识别重点区域，避免盲目裁剪
```

#### 场景 3: 处理长图（信息图、截图）

**问题**: 上传了 800×3000 的长截图

**自动处理**:
```
检测: 高 > 宽×2（长图）
判断: 这是信息图/完整截图

处理方案:
1. 不裁剪（保留完整信息）
2. 宽度限制: 缩放到 800px
3. 高度保持比例: 800×3000
4. 额外生成 Hero 图: 从顶部截取 800×420 → 缩放到 1200×630

输出:
- screenshot.webp (800×3000，完整版)
- screenshot-hero.webp (1200×630，Hero 版)

✅ 保留完整内容 + 生成社交分享图
```

#### 场景 4: 自动识别图片类型

**智能分类**:
```typescript
// 脚本自动判断图片用途
function detectImageType(image: Buffer): ImageType {
  const { width, height } = getImageDimensions(image);
  const ratio = width / height;
  
  if (ratio > 1.5 && ratio < 2) {
    return 'hero';  // 接近 1.9:1，适合 OG 图
  } else if (height > width * 2) {
    return 'infographic';  // 长图，可能是信息图
  } else if (width > 2000) {
    return 'chart';  // 超宽图，可能是图表
  } else {
    return 'regular';  // 普通插图
  }
}
```

**自动应用处理策略**:
- Hero 图: 裁剪到 1200×630
- 信息图: 保持完整，生成额外的 Hero 版
- 图表: 保持清晰度（质量 90，PNG 格式）
- 普通插图: 缩放到 800px 宽

### 2.3 图片数量规范

**每篇文章推荐图片数量**:
- 短文章（<1000 字）: 3-5 张
- 中等文章（1000-2000 字）: 5-8 张
- 长文章（>2000 字）: 8-12 张

**图文比例**: 文字:图片 ≥ 3:1（避免图片过多）

### 2.4 图片风格

**整体风格**:
- 🎨 **色调**: 明亮、温暖、舒适
- 🎨 **饱和度**: 中等（不刺眼，不灰暗）
- 🎨 **风格**: 现代、简洁、专业

**色彩方案**（参考 Tailwind CSS 配色）:
- 主色: 蓝色系（信任、专业）
- 辅色: 绿色系（活力、成长）
- 点缀: 橙色系（温暖、行动）
- 中性: 灰色系（背景、文字）

**禁止**:
- ❌ 过于花哨的特效
- ❌ 低分辨率、模糊的图片
- ❌ 有明显版权标识的图片
- ❌ 与主题无关的图片

## 三、文件命名规范

### 3.1 图片文件命名

**规则**:
1. 使用英文小写字母
2. 单词间使用连字符（-）分隔
3. 包含关键词
4. 简洁但描述性强

**格式**: `{主题}-{类型}-{序号}.{ext}`

**示例**:
```
✅ time-management-tips-hero.jpg
✅ countdown-calculator-screenshot-1.png
✅ productivity-chart-growth.png
✅ anniversary-reminder-flow.svg

❌ IMG_1234.jpg
❌ screenshot.png
❌ 时间管理.jpg
❌ Time Management Tips.jpg
```

### 3.2 博客文件命名

**格式**: `{slug}.md`

**slug 规则**:
- 使用英文小写字母
- 单词间使用连字符（-）
- 简洁但表达清晰
- 包含核心关键词

**示例**:
```
✅ why-i-built-daysfromtoday.md
✅ time-management-tips.md
✅ how-to-calculate-business-days.md

❌ article-1.md
❌ blog_post_2025_01_15.md
❌ 为什么我要做daysfromtoday.md
```

### 3.3 R2 存储路径

**格式**: `blog/{lang}/{post-slug}/{filename}.{ext}`

**示例**:
```
blog/zh/why-i-built/hero.webp
blog/zh/why-i-built/hero.jpg
blog/en/time-management-tips/screenshot-1.webp
blog/en/time-management-tips/chart-growth.png
```

## 四、SEO 优化清单

### 4.1 图片 SEO

#### Alt 文本规范

**规则**:
1. 描述图片内容（不超过 125 字符）
2. 自然融入关键词
3. 避免关键词堆砌
4. 不使用"图片"、"照片"等冗余词

**示例**:
```
✅ alt="时间管理的5个实用技巧信息图"
✅ alt="DaysFromToday倒计时计算器主界面截图"
✅ alt="工作日与自然日计算流程对比图"

❌ alt="图片"
❌ alt="screenshot"
❌ alt="时间管理 时间管理技巧 时间管理工具"（关键词堆砌）
```

#### Title 属性（可选）

**用途**: 鼠标悬停时显示，提供额外信息

**示例**:
```html
<img 
  src="..." 
  alt="时间管理的5个实用技巧信息图"
  title="点击查看完整信息图"
/>
```

#### 尺寸声明（必需）

**用途**: 防止 CLS（累积布局偏移）

**示例**:
```mdx
<BlogImage 
  src="..." 
  alt="..."
  width={1200}
  height={630}
/>
```

### 4.2 文章 SEO

#### Frontmatter 必需字段

```yaml
---
title: "文章标题（<60 字符）"
description: "文章摘要（<160 字符）"
date: "2025-10-10"
author: "Leon"
keywords: ["时间管理", "生产力", "倒计时"]
ogImage: "https://cdn.daysfromtoday.ai/blog/zh/hero-og.jpg"
---
```

#### 标题结构

**规则**:
- H1: 文章标题（仅一个）
- H2: 主要章节
- H3: 子章节
- H4: 细节小节

**示例**:
```markdown
# 文章标题 (H1)

## 第一章节 (H2)

### 1.1 子章节 (H3)

#### 具体要点 (H4)
```

#### 关键词策略

**规则**:
1. 主关键词出现在标题、H2、第一段
2. 相关关键词自然分布
3. 避免关键词密度过高（<3%）
4. 使用长尾关键词（如"如何计算工作日"）

## 五、写作风格指南

### 5.1 语言风格

**总体要求**:
- 📝 **清晰**: 小学六年级学生能看懂
- 💬 **口语化**: 像朋友聊天，避免书面语
- 🎯 **简洁**: 去掉冗余词汇，直奔主题
- ❤️ **温暖**: 有人情味，有情感共鸣

**示例对比**:
```
❌ "本文旨在探讨时间管理的多种策略及其实施路径"
✅ "这篇文章会教你 5 个超实用的时间管理技巧"

❌ "通过对数据的分析，我们可以得出如下结论"
✅ "看看这些数据，你会发现一个有趣的现象"
```

### 5.2 段落结构

**规则**:
1. 每段 3-5 句话
2. 每句话不超过 30 字
3. 段落间留白（1-2 行）
4. 使用列表、引用块增强可读性

**示例**:
```markdown
这是第一段，简短有力，直奔主题。不要写得太长，会让人疲劳。

这是第二段，延续上文，深入展开。可以用具体例子来说明。

**要点总结**:
- 第一点
- 第二点
- 第三点
```

### 5.3 开头与结尾

#### 开头（Hook）

**目的**: 吸引注意力，建立共鸣

**模板**:
1. **问题式**: "你是不是也有这样的烦恼？"
2. **故事式**: "去年春天，我遇到了一个难题..."
3. **数据式**: "你知道吗？90% 的人都低估了..."
4. **直接式**: "今天我要分享 5 个..."

**示例**:
```markdown
你是不是也有这样的经历：明明定了很多目标，
却总是忘记重要的日子？错过了生日、纪念日、项目截止日...

别担心，今天我要分享一个超简单的方法，
让你永远不会忘记重要的日子。
```

#### 结尾（CTA）

**目的**: 行动号召，增强互动

**模板**:
1. **总结式**: "总结一下，我们学到了..."
2. **问答式**: "你有什么时间管理技巧？欢迎留言分享！"
3. **工具式**: "现在就试试 DaysFromToday，开始管理你的时间！"

**示例**:
```markdown
## 总结

今天我们学到了 5 个时间管理技巧：
1. 使用倒计时提醒
2. 区分自然日和工作日
3. ...

现在就试试 [DaysFromToday](https://www.daysfromtoday.ai)，
让时间管理变得更简单！

你有什么时间管理技巧？欢迎在下方留言分享！
```

### 5.4 语气与称呼

**规则**:
- 使用"你"而非"您"（亲切感）
- 使用"我"而非"笔者"（真实感）
- 避免教条式（"应该"、"必须"）
- 多用鼓励式（"试试看"、"你也可以"）

**示例对比**:
```
❌ "用户应该养成良好的时间管理习惯"
✅ "试试这些方法，你也能管好时间"

❌ "笔者认为时间管理很重要"
✅ "我觉得时间管理真的很重要"
```

## 六、质量检查清单

### 6.1 发布前检查（Pre-publish Checklist）

#### 内容质量
- [ ] 标题吸引人，<60 字符
- [ ] 摘要清晰，<160 字符
- [ ] 开头有 Hook，吸引读者
- [ ] 结尾有 CTA，引导行动
- [ ] 段落结构清晰，易读
- [ ] 语言口语化，无生僻词
- [ ] 拼写和语法正确

#### 图片质量
- [ ] 每篇至少 3 张图片
- [ ] 图片清晰，无水印
- [ ] 图片与内容相关
- [ ] 图文比例合理（文字:图片 ≥ 3:1）
- [ ] Hero 图尺寸正确（1200×630）

#### SEO 优化
- [ ] Alt 文本完整（所有图片）
- [ ] 图片文件名符合规范
- [ ] 关键词自然分布
- [ ] 标题结构正确（H1-H4）
- [ ] Frontmatter 完整
- [ ] OG 图片设置正确

#### 技术检查
- [ ] 图片已上传到 R2
- [ ] 图片 URL 正确
- [ ] 内部链接正确
- [ ] 外部链接正常（target="_blank"）
- [ ] MDX 组件正常渲染

#### 性能检查
- [ ] 图片已优化（WebP + JPEG）
- [ ] 图片大小合理（<100KB/张）
- [ ] 懒加载生效
- [ ] LCP <2.5s（本地测试）

### 6.2 发布后检查（Post-publish Checklist）

#### 功能验证
- [ ] 文章在列表页正常显示
- [ ] 文章详情页正常打开
- [ ] 图片正常加载
- [ ] 移动端显示正常
- [ ] 中英文切换正常

#### SEO 验证
- [ ] OG 图片预览正常（Twitter/LinkedIn）
- [ ] 提交到 GSC
- [ ] 提交到 Image Sitemap

#### 社交推广
- [ ] 分享到 Twitter
- [ ] 分享到 LinkedIn
- [ ] 更新 Newsletter（如有）

### 6.3 定期审查（Monthly Review）

**每月检查**:
- [ ] 查看 GA4 数据（流量、停留时间、跳出率）
- [ ] 查看 GSC 数据（搜索词、排名、点击率）
- [ ] 查看图片 SEO 数据（Images 流量）
- [ ] 优化表现差的文章
- [ ] 更新过时内容
