## 📝 Markdown 格式说明

每个配置文件采用以下格式：

```markdown
# 🇨🇳 中国节假日 (China Public Holidays)

> **数据来源**: 国务院办公厅 + Nager.Date API  
> **最后更新**: 2025-10-08  
> **维护状态**: ✅ 已人工验证  
> **验证者**: Leon  

---

## 2025年

### 元旦 | New Year's Day
- **日期**: 2025-01-01
- **类型**: 公共假期 (Public Holiday)
- **全国性**: 是
- **说明**: 法定节假日，调休3天

### 春节 | Spring Festival
- **日期**: 2025-01-29 ~ 2025-02-04
- **类型**: 公共假期 (Public Holiday)
- **全国性**: 是
- **说明**: 农历新年，法定假期7天
```

### 字段说明

#### 元数据区域

- **数据来源**: 官方网站或 API 名称
- **最后更新**: YYYY-MM-DD 格式
- **维护状态**: 
  - `✅ 已人工验证` - 数据已验证准确
  - `⏳ 待验证` - 初始化数据，待人工验证
  - `⚠️ 部分验证` - 部分年份已验证
- **验证者**: 验证人员名称（可选）

#### 节假日条目

- **日期**: 
  - 单日: `2025-01-01`
  - 连续多日: `2025-01-29 ~ 2025-02-04`
  - 不连续多日: `2025-01-01, 2025-01-02, 2025-01-03`
- **类型**: 
  - `公共假期 (Public Holiday)` - 法定假期
  - `银行假期 (Bank Holiday)` - 银行休息日
  - `地区假期 (Regional Holiday)` - 地区性假期
  - `宗教节日 (Religious Holiday)` - 宗教节日
  - `纪念日 (Observance)` - 纪念日（不一定放假）
- **全国性**: `是` 或 `否`
- **说明**: 可选，添加额外说明（如调休安排）

## 🛠️ 使用方法

### 初始化所有国家数据

```bash
npm run holidays:init
```

这将从 Nager.Date API 抓取所有国家的 2025-2028 年数据并生成 Markdown 文件。

### 更新单个国家

```bash
npm run holidays:update CN
```

### 验证数据格式

```bash
npm run holidays:validate
```

## ✏️ 手动编辑指南

### 1. 打开对应国家的文件

```bash
vim data/holidays/CN.md
```

或使用任何 Markdown 编辑器。

### 2. 验证数据准确性

对照官方源检查：
- 日期是否正确
- 名称是否准确
- 类型是否合适
- 是否有遗漏

### 3. 添加中文翻译

确保中文名称准确且符合习惯用法。

### 4. 补充说明

添加有用的信息，例如：
```markdown
- **说明**: 农历新年，法定假期7天
  - 调休安排：1月26日（周日）、2月8日（周六）上班
  - 高速公路免费：1月28日 00:00 - 2月4日 24:00
```

### 5. 更新元数据

验证完成后，更新元数据：

```markdown
> **维护状态**: ✅ 已人工验证  
> **验证者**: 您的名字  
> **验证日期**: 2025-10-08  
```

### 6. 提交变更

```bash
git add data/holidays/CN.md
git commit -m "feat: 人工验证 2025-2026 年中国节假日"
git push origin main
```

## ❓ 常见问题

### Q: 为什么使用 Markdown 而不是 JSON？

**A:** Markdown 更易于人工编辑，支持富文本说明，Git Diff 更清晰，便于版本管理。

### Q: 如何添加新年份的数据？

**A:** 在对应国家的 Markdown 文件中添加新的年份章节，格式保持一致即可。

### Q: 数据更新后多久生效？

**A:** 提交到 Git 后，Vercel 自动部署，通常 1-2 分钟内生效。

### Q: 如何处理移动假期（如复活节）？

**A:** 使用日期范围或多个日期，必要时添加说明。

### Q: 发现数据错误怎么办？

**A:** 直接修改对应的 Markdown 文件，更新维护日志，提交即可。
